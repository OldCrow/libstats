## Regenerating

```sh
cmake --preset release -G Ninja
cmake --build build-release --target accuracy_sweep
build-release/tools/accuracy_sweep sweep.csv
<python-with-mpmath> tools/accuracy_vs_mpmath.py sweep.csv
```

`accuracy_sweep` (owned separately, `tools/accuracy_sweep.cpp` +
`tools/CMakeLists.txt`) emits the `dist,method,p1_bits,p2_bits,x_bits,
scalar_bits,batch_bits` CSV described in that tool's own header comment.
`accuracy_vs_mpmath.py` runs its oracle self-checks first (exits non-zero
without writing anything if any fails), then rewrites the generated block
for the sweep's ISA in place — one block per ISA, labelled by the sweep
banner's `isa=` value (`<!-- BEGIN GENERATED isa=<ISA> -->` …, markers on
their own lines); a sweep from
a new ISA appends a block after the last existing one, and `--isa` overrides
the label. Do not hand-edit anything between a `BEGIN GENERATED` /
`END GENERATED` pair — the next regeneration on that ISA overwrites it.

## Reading the tables

- `max_abs` / `max_rel` / `p99_rel`: worst absolute error, worst relative
  error, and 99th-percentile relative error across the swept rows for that
  (distribution, method, source) group, against the mpmath reference.
- Relative error is scored down to DBL_MIN. Below it the error is the ULP
  distance in subnormal units (2^-1074), reported on the relative scale as
  ULPs × 2^-52, so a `max_rel` from a subnormal reference reads in ULPs, not
  as a true relative error. A reference at or below half the smallest
  subnormal rounds to 0 in double and scores as exact 0. Until 2026-10-11 any
  reference below 1e-290 was scored by absolute error. `max_rel` and
  `p99_rel` therefore shift at the first regeneration under this rule
  without any library change: Cauchy `cdf` went 2.1e-12 → 2.8e-16 (the old
  figure was the oracle's own cancellation), and Cauchy `pdf` now shows
  subnormal-reference ULPs.
- `survival` rows are scored exactly as `cdf` rows: relative/ULP error,
  `law_frac` for references below 1e-3, the same contract checks. A
  survival of 0 where the reference rounds to a nonzero double is listed as
  ZERO-COLLAPSE, reported but not a contract violation.
- `law_frac(cdf)`: for `cdf` rows whose reference `F < 1e-3` only, the
  worst observed relative error expressed as a **fraction of the
  achievable-accuracy law** `rel(F) ~ |ln F| * 2^-52`, established in
  `tests/test_lognormal_cdf_accuracy.cpp`'s `law_budget` comment (its
  pinned gate budget adds headroom on top of this same bare law; this
  column reports the bare law). A large `max_rel` in the deep tail
  alongside a `law_frac` at or below roughly 1 is **the law, not a
  defect** — a flat relative-error budget is mathematically unachievable
  at double precision in that regime, for any implementation of these
  closed forms. Treat a `law_frac` well above 1 as the signal worth
  investigating, not the raw `max_rel` next to it.
- `batch_vs_scalar`: worst absolute/relative disagreement between the
  batch (span-overload) and scalar paths on the same rows, shown on the
  `batch` row.
- `worst_x`: the input at which `max_rel` was observed (for `quantile`
  rows, this is the probability `p`, not a domain point — see the input
  contract in `tools/accuracy_vs_mpmath.py`'s header comment).
- Any contract violation (NaN-in/NaN-out, `+-inf` boundary behavior) is
  reported as its own row, separate from the error statistics above — it
  is never folded into `max_abs`/`max_rel`/`p99_rel`. The full list is
  the appendix at the end of the generated block.

Five metric artifacts to read past — each is a property of the metric at
that row, not a defect:

- **Von Mises `cdf` relative columns (blocks before v2.5.0).** Up to
  v2.4.1 the Bessel-series CDF was constructed and gated (#51) in
  **absolute** terms, so its deep-tail `max_rel`/`law_frac` values were
  astronomically large and meaningless (an absolute-1e-16 error against
  `F ~ 1e-89` read as `rel ~ 1e+73`). From v2.5.0 the CDF is a quadrature
  that meets the relative law in both tails (`law_frac` below 1), so its
  relative columns now read like any other `cdf` row.
- **`logpdf` relative error near its zero crossing.** Where
  `logpdf(x) ~ 0` (e.g. exponential at `lambda*x ~ ln(lambda)`), any
  fixed absolute error reads as a large relative one. Read `max_abs`.
- **`max_abs` on singular-density rows.** Beta/Weibull with shape < 1
  have integrable singularities; near them the density reaches `1e+298`
  and a `max_abs` of `1e+93` alongside `max_rel ~ 1e-10` is the value's
  magnitude, not the error's.
- **Quantile rows at extreme `p`.** The oracle's reference quantiles run
  to `1e-30000` and beyond, far outside double range; where the library
  saturates (support bound, grid edge, `+-inf`), `max_rel ~ 1` records
  the saturation point, not solver accuracy. Discrete quantiles follow the
  library rule: for p ≤ ½ the smallest k with F(k) ≥ p, for p > ½ the
  smallest k with S(k) ≤ 1 − p. In exact arithmetic both select the
  right-continuous inverse, and the oracle scores that rule (Discrete by its
  library-CDF tie rule), so the one-count `rel = 1.0` lattice rows of earlier
  generations no longer appear; a residual one-count difference comes from
  the library's rounding of S. <!-- R6b: confirm no lattice rows remain -->
- **References beyond double range score a matching-sign `±inf` as
  correct (comparator rule since 2026-09-03).** A reference with
  `|ref| ≥ 2^1024 − 2^970` (the binary64 rounds-to-inf midpoint) has
  `±inf` as its correctly rounded double, so a library `±inf` of the
  reference's sign is scored correct; a finite library value there
  *failed to overflow* and is still flagged, and references between
  `DBL_MAX` and the midpoint keep the relative-error path. History: the
  comparator originally tested `mp.isfinite` — *mpf*-finiteness, not
  double-representability — and flagged 8 such rows on the v2.4.0
  AVX-512 grid (`fisher_f`/`inverse_gamma` shape-0.01 tails, references
  `2.5e+317` … `7.4e+2939`) as `reference is finite (…), decoded to inf`
  violations; the extension pass documented them as a hand-exclusion
  artifact rather than change classification mid-PR. The rule was then
  adopted deliberately in the same-day accuracy-fix pass (see that
  section below), with the reclassification of any same-shape frozen
  rows recorded there instead of left to per-comparison hand exclusion.

### Two accuracy findings worth carrying forward

Neither is a contract violation, and neither was fixed here — this is a
characterization pass. *(Both were fixed the same day in the
accuracy-fix pass below; kept as the record of what the extension sweep
measured. The TruncatedNormal fix ended up one level deeper than the
survival-form suggestion here: near the bound, `q_alpha − q_xi` is still
a difference of two independently rounded values, so the numerator is
evaluated directly by a Hermite series instead.)*

- **`truncated_normal` `cdf` loses relative accuracy approaching the
  lower bound**: `max_rel = 0.318` at `x = lo + 1 ulp` on the (10, 12)
  window (library `3.150e-15`, oracle `4.622e-15`) and `0.158` on
  (−2, 2), decaying to 1e-5 by `lo + 4e-11` and to 1e-8 by `lo + 1e-9`.
  That decay profile is the signature of a fixed absolute error in a
  cancelling difference, and `src/truncated_normal.cpp` confirms it: the
  CDF numerator is `HALF*erfc(-xi*INV_SQRT_2) - phi_alpha`, i.e.
  `Φ(ξ) − Φ(α)` — the very form #57 rewrote *Z* out of, applied to the
  numerator. The class already caches `q_alpha`/`q_beta`, so the
  survival-form numerator (`q_alpha − q_xi` for α ≥ 0, reflected for
  β ≤ 0) is available without new state. `law_frac = 4.3e+13` flags it
  by the doc's own rule. The `max_abs` stays at 1.5e-15 throughout.
- **`fisher_f` `cdf` collapses to 0 in the far power-law tail**:
  `F(0.01, 0.01).cdf(2.4e-322) = 0.0` against a true `0.0123`
  (`max_abs = 0.0123`, `max_rel = 1.0`, `p99_rel = 3.9e-9` — one isolated
  row, not a broad loss). `d1*x` underflows below the smallest denormal,
  taking `y = d1x/(d1x + d2)` to 0 with it; a log-space `y` would not.
  Note the round trip: that `x` is the library's *own* `getQuantile`
  output, so quantile→cdf does not close there.

## v2.4.0 accuracy fixes: 57 → 34 on the 9210-row grid (2026-09-03, same day)

The extension's findings were fixed the same day — four library fixes
plus one comparator rule, each behind a fail-first gate shown failing on
the unfixed build (MSVC/Zen 4):

- `fix(gamma)`: deep-tail quantile escape (log-domain small-p seed,
  mean fallback, relative-in-p stopping, self-repairing bisection
  bracket) and batch-CDF `+inf` lanes pinned to 1. En route the relative
  stopping test exposed that the old absolute `|cdf − p| < 1e-12` had
  been silently accepting wrong deep-tail quantiles without any
  violation — `quantile(1e-15)` at (α=1e4, β=1e-3) returned a point
  whose true CDF is ~1e-50.
- `fix(fisher_f)`: the CDF/SF beta argument switches to
  `y = x/(x + d2/d1)` when `d1·x` is subnormal, so the far power-law
  tail no longer collapses to 0 and quantile→cdf closes down to
  `DBL_TRUE_MIN`.
- `fix(truncated_normal)`: near-lower-bound CDF numerator by Hermite
  series (|α|·d ≤ 1/4 band); all eight gate points now ~1e-14 from
  the dps=60 references, batch lanes bit-identical to scalar.
- `fix(oracle)`: the beyond-double-range rule under "Reading the

## Findings (historical — v2.3.0 initial characterization, 2026-08-19)

What the FIRST sweep surfaced, beyond confirming the four pinned gates.
Status 2026-09-04: the batch-NaN class was fixed in v2.3.1 (#102/#105 —
0 rows on all three ISAs); the gamma-family ±inf and deep-tail-quantile
items were fixed in v2.4.0 (#130, the `fix(gamma)` pass); the remaining
±inf rows are #103's enforcement scope and the rest are filed as
#136/#137/#138/#141. Kept as the record of what characterization finds:

- **Batch NaN propagation is inconsistent** (35 rows, 8 distributions:
  uniform, gamma, chi-squared, laplace, pareto, weibull, beta,
  von Mises). Scalar paths propagate NaN; the batch paths return finite
  values instead — uniform batch `pdf(NaN)` returns the in-support
  density (the NaN comparison silently takes the in-range branch),
  pareto batch `cdf(NaN)` returns `0.999...`.
- **`+-inf` inputs**: gamma/chi-squared/rayleigh/weibull scalar
  `pdf`/`logpdf` return NaN at `+inf` where the limits (`0`, `-inf`)
  exist; chi-squared/gamma **batch** `logpdf(+inf)` instead returns the
  clamp constant `-4605.0` (`ln(1e-2000)`). Von Mises applies a
  consistent saturation convention (`pdf -> 0`, `logpdf -> -inf`,
  `cdf -> 0/1`) in both paths — recorded here as the convention.
- **Quantile extreme-`p` behavior**: gamma and chi-squared quantiles
  return NaN for some deep-tail `p`; pareto returns `+inf`, student-t
  `-inf`, where finite doubles exist; cauchy loses all accuracy at
  `p = 1e-300` (`rel = 1.0`).
- **Large-parameter CDF accuracy**, oracle independently validated by
  direct quadrature to `1e-44`: binomial `n = 1e6` is off by `1.3e-2`
  relative **at the mean**; chi-squared `k = 1e5` by `8.3e-6`; beta
  `(1e4, 1e4)` by `4.1e-9`. The corvus adoption line items (#47/#52,
  incomplete gamma/beta cores) are the planned remedy for this class.
